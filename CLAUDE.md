# CLAUDE.md

Guía para trabajar en este repositorio. Traductor IA traduce videojuegos del inglés al **español de España** con un
modelo local servido por **Ollama**. Soporta RPG Maker MV/MZ, Ren'Py, Unity (BepInEx + XUnity.AutoTranslator) y
CSV de idiomas (Godot, DKTools…). El código, los comentarios, los mensajes de log y los de commit están **en
español**.

## Tecnologías

- **Python 3.10.** El entorno es `venv_traductor/` (lo crea `setup.bat`), y en Windows su intérprete es
  `venv_traductor/Scripts/python.exe`.
- **Ollama** en `http://localhost:11434` (la API es `/api/generate`), con los modelos `IA_Traductora_v4` (para
  juegos con ficha de personajes) e `IA_Traductora` (sin ella).
- **Dependencias:**
  - Cliente HTTP y proxy: `requests`.
  - Monitor web: `flask` y `flask-cors`.
  - Bandeja del sistema: `pystray` y `pillow`.
  - Partidas `.rpgsave`: `lzstring`.
  - Lectura de archivos de Unity: `UnityPy`, que es opcional y `setup.bat` no instala (`pip install UnityPy`).
- **Entrenamiento (opcional):** PyTorch CUDA 12.1, Unsloth (QLoRA), `trl` y `peft`, con exportación a GGUF y
  `Modelfile_v*`.
- **Unity:** un plugin de BepInEx en C# (`traductor/motores/recursos/AutoProxyPlugin.cs/.dll`) arranca
  `ollama_proxy.py` al abrir el juego.

## Comandos

```bash
# Pruebas: unittest, no pytest. No necesitan Ollama ni juegos (el modelo se simula)
venv_traductor/Scripts/python.exe -m unittest discover -s tests
venv_traductor/Scripts/python.exe -m unittest tests.test_unity_tablas      # un archivo

# Flujo principal
python 0_analizar_juego.py --ruta "<juego>"                  # ficha de personajes (Paso 0)
python 1_traducir_juego.py --ruta "<juego>" --modo seguro    # o --modo turbo / --turbo
python 1_traducir_juego.py --ruta "<juego>" --solo-genero    # juego ya traducido: solo retraduce lo afectado
python 1_traducir_juego.py --ruta "<juego>" --motor Unity --pretraducir --juego <perfil>
python ollama_proxy.py --juego <perfil> --puerto 11435       # proxy de XUnity a mano
iniciar_monitor_bandeja.bat                                   # Centro de Control (GUI)

# Entrenamiento
python preparar_datos_v2.py
python entrenar_v2.py --version N [--casos-dificiles] [--solo-datos]
ollama create IA_Traductora_vN -f Modelfile_vN
python 9_evaluar_genero.py --modelo IA_Traductora_vN          # medir antes de usar un modelo
python 9_evaluar_genero.py --banco --modelo IA_Traductora_vN  # banco fijo inventado (semilla fija, sin juegos)
python 9_evaluar_genero.py --comparar <banco_A.json> <banco_B.json>
```

Opciones útiles de `1_traducir_juego.py`: `--juego` (perfil de `workspace/`), `--modelo X|auto`, `--archivo`,
`--motor RPGMaker|RenPy|Godot|Unity`, `--sin-monitor`, `--debug`.

## Arquitectura

```text
0_…9_*.py               pasos del flujo de trabajo (CLI); 1_traducir_juego.py orquesta todo
ollama_proxy.py         servidor HTTP que XUnity llama en directo (CustomTranslate, puerto 11435)
traductor/
  config.py             rutas, perfiles de juego (workspace/<juego>/), modelo automático, variables de entorno
  ollama.py             OllamaTranslator: prompt, caché por modelo, puerta de calidad, reintentos y autocorrección
  prompts.py            INSTRUCCION y PLANTILLA: las MISMAS en entrenamiento y en inferencia
  texto.py              limpieza de respuestas, etiquetas y códigos del juego, evaluar_traduccion() y gravedad()
  personajes.py         FichaPersonajes, InfoLinea (lo que el motor sabe de la línea), resolver_linea, concordancia
  genero.py             corrección determinista de género en 1.ª, 2.ª y 3.ª persona (funciones puras)
  ambiguas.py           palabras con dos sentidos (chest → pecho/cofre), vulgarismos y órganos inventados
  espana.py             vocabulario de Latinoamérica → España (enojado, lindo, apúrate, extrañar, coger sexual)
  gramatica.py          determinante + sustantivo femenino (se corrige), "No finge" y tartamudeo "I-It" (se reintenta)
  modismos.py           frases hechas y palabrotas: pista en el glosario y detección del calco ("maldita buena")
  analizador.py         Paso 0: deduce protagonista y personajes con su género, con evidencia
  xunity.py             leer y escribir _AutoGeneratedTranslations.txt (escapado oficial, edición línea a línea)
  csv_locales.py        lectura y escritura de CSV de idiomas conservando el BOM y los finales de línea
  unity_dialogos.py     quién habla en Unity (objetos Dialogue/Character leídos con UnityPy)
  nombres_hablantes.py  tabla de nombres de las cajas de diálogo (Paso 5)
  progreso.py           estado compartido con el monitor (EstadoProgreso)
  motores/              detector.py, rpgmaker.py, renpy.py, csv_locales.py, unity.py, unity_tablas.py
herramientas_extra/     Centro de Control (monitor_bandeja.py), monitor web, editor de personajes, respaldos…
glosarios/              diccionarios genéricos y plantillas *.ejemplo.json
tests/                  unittest; tests/datos/ con archivos de prueba inventados
```

**Flujo de una frase:**
1. El motor extrae el texto y, si lo sabe, un `InfoLinea` (hablante, código, opción, sexo).
2. `OllamaTranslator.translate()` / `traducir_textos()` resuelve el contexto con `resolver_linea(ficha, texto, info)`.
3. Construye el prompt: INSTRUCCION, contexto del juego, glosario y la frase anterior en modo seguro.
4. Llama a Ollama.
5. `limpiar_respuesta` deja solo la traducción (y `postprocesar_traduccion` aplica `espana.py`).
6. `evaluar_traduccion` revisa el resultado; si hay problemas graves, o leves de `PROBLEMAS_LEVES_REINTENTO`
   (cifras, calcos, "No finge", tartamudeo, género del oyente por turnos), reintenta con una nota. "ustedes" solo
   se avisa.
7. `aplicar_concordancia` corrige el género.
8. Guarda en la caché.
9. El motor reinyecta la frase respetando los códigos del juego.

**Motores:**
- **RPG Maker:** `www/data/*.json`, con copia `.bak` del original.
- **Ren'Py:** `game/tl/`. `oyentes_del_archivo` saca a quién se habla por los turnos (A-B-A) e
  `InfoLinea.oyente` lo pasa como pista; si la 2.ª persona lo contradice, se reintenta (nunca se corrige solo).
- **CSV de idiomas:** columna de español.
- **Unity:**
  - `inyectar_unity()` escribe `AutoTranslatorConfig.ini` (Endpoint=CustomTranslate) e instala el plugin.
  - Con `--pretraducir`, `unity_tablas.py` traduce las tablas `TextAsset` (CSV/TSV con columna EN) de `.assets`,
    `level*` y `data.unity3d`, y las escribe en el archivo de XUnity.
  - `--solo-genero` repasa ese archivo (`repasar_xunity`).

**Perfil de juego**, en `workspace/<juego>/` (privado): `personajes.json`, `glosario.json`, `contexto.txt`,
`nombres_protegidos.json`, `ajustes.json` (modelo, `carpeta_juego` y, en Unity, `tablas_unity`: tablas omitidas,
columna de hablante → personaje de la ficha y variables `{flag=…}` → nombre), `cache/` y `casos_dificiles.jsonl`.
`config.resolver_juego()` deduce el perfil del nombre de la carpeta, o de `carpeta_juego` si ese nombre no sirve
(por ejemplo, si está en chino).

## Reglas del código

- **`prompts.INSTRUCCION`:** no cambiarla sin regenerar el dataset y reentrenar, porque el modelo afinado depende
  de ella. Si hay que añadir algo, va detrás (contexto, glosario, notas de reintento).
- **Caché:** la clave depende del texto y del contexto, así que al cambiar el contexto deja de coincidir. Para
  reaprovechar lo hecho se usa `--solo-genero` (`reaprovechar_cache_de`, `sembrar_traduccion`). Nada que falle la
  puerta de calidad entra en la caché.
- **Género:** las correcciones son conservadoras (ante la duda, no tocar). La 2.ª persona solo se corrige si se
  nombra a quien escucha. Si el hablante está en la ficha, manda la ficha sobre `InfoLinea.genero`.
- **Archivos del juego:** conservar byte a byte lo que no cambia, es decir, BOM, CRLF/LF y escapado
  (`xunity.editar_lineas`, `csv_locales.leer_lineas/escribir_lineas`). Nunca reescribir un archivo entero si basta
  con editar líneas.
- **Códigos del juego** (`\C[n]`, `\N<…>`, `\!`, `\|`, `\n`, `\CL`, `{0}`, `{wc}`, `<color=…>`): deben sobrevivir a
  la traducción. Si el modelo los pierde, se recolocan en código (`forzar_etiquetas`, `_colocar_pausas`,
  `ajustar_saltos`), no en el prompt.
- **Pruebas:** cada cambio de comportamiento lleva su prueba en `tests/`, con nombres y frases **inventados**.
- **Banco fijo** (`tests/datos/banco_traduccion.json`): no cambiar los casos que ya existen (las medidas dejarían
  de compararse); añadir casos nuevos con otro `id`. Antes de adoptar una regla de reintento nueva, comprobar en el
  banco que no empeora (con "ustedes" empeoraba).
- **Estilo:** nombres de funciones y variables en español, `from __future__ import annotations`, logging con
  `log = logging.getLogger(__name__)` y mensajes claros para el usuario.

## Repositorio público y datos privados

- El repo es público y debe ser **neutro**: ni nombres ni frases de juegos reales, ni rutas personales, en el
  código, las pruebas, el README o los commits.
- Lo propio de cada juego va a `workspace/`, `datasets/`, `modelos/` o `privado/`, todo ignorado por `.gitignore`.
  Los scripts hechos para un juego concreto van a `privado/` o a `.git/info/exclude`.
- Antes de hacer un commit hay que revisar el diff en busca de nombres de juegos o personajes, rutas `X:\…` y
  correos.
- Los mensajes de commit van en español y terminan con la línea `Co-Authored-By` que indique la sesión.
- Hay que mantener el README al día cuando se añade una función o una opción.

## Trabajar con juegos instalados

- **No escribir directamente en la carpeta de un juego.** Primero se prepara una copia en `workspace/<juego>/…`
  con `antes/` (original) y `nuevo/` (corregido).
- **Instalar solo si el usuario lo pide.** Antes, comprobar que el juego está cerrado (`tasklist`) y que el hash del
  archivo del juego coincide con el de `antes/`.
- **La GPU se comparte con los juegos.** Antes de traducir o entrenar, mirar `nvidia-smi` y los procesos. Si se
  abre un juego, Ollama puede devolver errores 500 sueltos; el traductor reintenta solo.
- **Ver el texto original:**
  - RPG Maker: `www/data/*.json.bak` o los `.original`.
  - CSV de idiomas: `<archivo>.csv.original`, junto al CSV.
  - Partidas guardadas: `.rpgsave` en LZString base64; pueden guardar referencias (`{actor_01}`) en vez del texto.

## Qué modelo de Claude usar

Al proponer el siguiente paso, o al listar tareas pendientes, di también **con qué modelo y con qué esfuerzo
conviene hacer cada una** (el usuario cambia el modelo con `/model` y el esfuerzo con `/effort`). Criterio:

- **Opus, esfuerzo alto (`high` o `xhigh`)** cuando hay que decidir o juzgar: revisar datos de entrenamiento o
  casos difíciles uno a uno, auditar género en frases ambiguas, diseñar una regla nueva, depurar algo que no se
  entiende.
- **Sonnet, esfuerzo medio (`medium`)** cuando la receta ya está clara: aplicar una corrección conocida, pasar
  pruebas, instalar con copia de respaldo, actualizar README y plan, hacer commits, lanzar un entrenamiento.
- **Esfuerzo bajo (`low`)** para lo mecánico y corto: renombrar, formatear, copiar archivos.

Si una tarea mezcla varias, di cuál parte es de cada modelo y esfuerzo.

## Cuándo limpiar la conversación

Avisa al usuario de cuándo conviene `/clear` o abrir una conversación nueva, porque una conversación larga se
resume y se pierden detalles. Dilo al cerrar una tarea, junto al siguiente paso, en una línea. Conviene:

- **Al terminar un bloque** (commit hecho y subido, o plan actualizado) y que lo siguiente no dependa de lo
  anterior: otro juego, otro bloque del plan, otro tipo de trabajo.
- **Antes de una espera larga** (un entrenamiento, una traducción de horas): no hace falta tener todo el contexto
  mientras se espera, y al volver se retoma desde el plan.
- **Cuando la conversación ya se ha resumido varias veces** o notes que repites cosas que ya estaban decididas.

No conviene en medio de una corrección a medias ni cuando el siguiente paso usa lo que acabas de descubrir. Antes
de recomendarlo, deja el estado escrito en `docs/PLAN_MEJORAS_TRADUCCION.md` (qué se hizo, qué queda y las copias
de seguridad), para que la conversación nueva pueda seguir leyendo solo ese archivo.

## Trampas del entorno (Windows + Git Bash)

- **Los heredocs de Bash se comen las barras invertidas:** las expresiones regulares y los códigos (`\n`, `\CL`)
  se rompen. Para código con barras invertidas hay que usar las herramientas Write/Edit, o `chr(92)` en Python.
- **`sed -i` convierte CRLF en LF.** No usarlo en archivos de juego; mejor editar con Python y `csv_locales`.
- **Salida de consola con tildes o caracteres chinos:** `PYTHONIOENCODING=utf-8`, o `sys.stdout.reconfigure(encoding="utf-8")`.
- **No hay pytest instalado:** se usa `python -m unittest`.
- **Rutas de juego con espacios o en chino:** usar rutas absolutas entre comillas; con UnityPy, `UnityPy.load(str(ruta))`.
